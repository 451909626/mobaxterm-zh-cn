# 26.5 起的版本适配

最低目标版本为 26.5，支持模型分为两部分：菜单启动器按产品信息和最低版本识别程序；完整界面构建按已登记的精确版本和官方文件摘要选择补丁。

## 目前的范围

| 上游版本 | 完整界面清单 | 状态 |
|---|---|---|
| 26.5.0.5542 Home Portable | `patches/26.5.0.5542/` | 已发布 R2.7；源码 R2.8 已通过构建及自动检查，本修订工具栏界面复测待完成 |
| 26.6.0.5560 Home Portable | `patches/26.6.0.5560/` | R2.13 预发布，合并会话、二级窗口、动态菜单及连接提示补译；构建与自动检查通过，新增范围完整实屏验收待完成 |
| 尚未登记的后续版本 | 需新增版本目录 | 可只读识别，不修改其 EXE |

26.5 和 26.6 各自有独立的官方输入摘要、窗体属性位置、资源摘要、运行时文字位置及重建结果摘要。26.6 中额外的 5 处 RDP 翻译属性未套用于 26.5。

工具栏的 `HelpKeyword` 同时用于显示标题和保存、匹配布局，必须保留官方英文值。R2.8 恢复两版各 14 处此类标识，主工具栏标题因此保留英文；不得为了标题中文而再次修改它们。

进一步跟踪发现，26.6 的布局加载还直接读取 `Caption`。R2.9 同时适配标题显示与两处布局读取：屏幕显示中文，已知按钮的布局识别读取原有英文标识；未知控件保留原生行为。该代码适配按精确版本和三个原调用字节限定，26.5 未登记，仍使用 R2.8 的英文工具栏标题。

R2.10 补译 26.6 设置页 25 个下拉控件的 85 条选项文字，同时补译 25 处默认显示文字。选项数量、顺序和序号保持一致。默认主页、新标签页和 X11 缩放不是纯显示文字：其六处读取与保存调用经精确字节校验，加载旧配置时识别原英文值，保存时继续写入原英文值；自定义会话名称及数值 DPI 走原生逻辑。键盘布局代码、X11 引擎版本和 Shell/皮肤名称保持原值。此补译未套用于 26.5。

R2.11 增加 35 个会话下拉控件、15 个二级窗口下拉控件及遗漏按钮的补译。SSH/WSL 桌面、串口校验、Mosh、浏览器、隧道代理、目录模板等实际连接或保存字符串继续使用原文；旧英文查询与中文列表兼容，自定义配色和动态名称保持原样。字体编码仅翻译说明，编码名、终端类型、引擎及算法标识保留。内置定制器资源中的目录模板也使用独立适配，但本项目仍只验证对应 Home 便携原包，不能据此声称 Professional 版本已验证。新增适配严格限定 26.6.0.5560 的原字节与参数来源，不套用于 26.5。

终端菜单启动器只修改命令编号与原英文同时匹配的已知项目。未来版本改变菜单名称、编号或窗口结构时，可能保留英文或无法匹配；需在真实版本发布后复核。测试中的合成 27.0 版本文件只用于检查版本选择逻辑，没有证明真实未来版本的兼容性。安装版、Professional 版及其他系统代码页不在已验证范围内。

R2.12 修正左侧会话栏右键菜单在弹出时覆盖资源翻译的 22 处动态文字。菜单中的数量和会话名称继续按原逻辑拼接，操作事件、命令、会话树标识与配置保持原样；这部分翻译由主程序本身提供，直接运行主 EXE 时也生效。此次改动未套用于 26.5。

R2.13 在连接及凭据提示的显示阶段翻译已知文字，保留主机名、账号、指纹和证书字段的原始字节。通用消息框仍以原英文正文处理“不再显示”的记录，“更多信息”布局判断也先使用英文；弹窗关闭后恢复内部标题，原生确认、取消及关闭结果不变。保存密码和主密码输入框的密码字段不参与转换。未知或有歧义的提示保持原文；主机身份验证、信任记录和密码加密方式不因翻译而改变。另补译指纹详情标签及七条原生主密码警告，不将这种本地显示适配扩大为所有远端程序输出、系统认证窗口或嵌入组件均已汉化。此补译未套用于 26.5。

## 为什么完整界面仍然需要清单

资源位置和引用会随升级变化。取消固定输入校验，或者把旧版地址直接用于新版，可能改到功能数据。当前工具先读取版本、验证原始文件，再在临时副本上修改，核对窗体结构、非资源区段和最终摘要，最后生成新目录。原版文件和现有汉化目录保留原样。

可先运行 `scripts/inspect_upstream.py` 了解输入情况。未适配版本返回检测到的版本和原因；构建入口会停止，不自动猜测补丁位置。

## 维护者增加新版

1. 从官方取得对应 Home 便携包，在本地核对版本信息、签名、原包和三个文件的 SHA-256；不上传厂商文件。
2. 新建 `patches/<完整版本>/`。依据组件路径、显示属性类型与原值摘要重新匹配翻译，确认新增或删除项目；不能只复制旧版索引或更新版本号。
3. 对每处运行时文字重新核对原字节、固定长度、引用位置和代码区段。保留字段白名单、命令和路径保护。
4. 生成并复核目标资源摘要、完整输出摘要和数量，将该版本加入 `patches/index.json`。原有版本清单保留。
5. 运行测试和实际重建，检查设置、新建会话、搜索、会话历史、关闭会话确认及终端菜单，更新验证记录中的实际进度。
6. 运行发布检查，确保 Git 中只有源码、必要翻译数据和脱敏的检查图。
